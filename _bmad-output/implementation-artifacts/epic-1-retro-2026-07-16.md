## What Went Well

- **The gate works.** Cognito auth + atomic invite-key redemption live-proven end-to-end, including the concurrent-double-redemption race (AD-16), the compensating-delete path (exercised inadvertently and worked), and the revoked-key rejection path (proven for real during this retro's key revocation). Tony's one-line verdict: "Cognito's working — one can issue a key and prevent random signups."
- **Story-to-story intelligence transfer.** 1.1's hard lessons (SSM parameter bridge vs data-group refs, never-fake-auth, custom table names impossible in Amplify Gen 2) were written into 1.2–1.4's specs as binding constraints. 1.2's Lambda deployed clean first try; no lesson was re-learned.
- **Verification infrastructure compounding.** The typecheck gate, added mid-review in 1.1, immediately caught the epic's worst bug (silent no-op table-name override that would have broken every signup). Live sandbox verification caught `clientMetadata`-on-`confirmSignUp`, the USER_AUTH auto-sign-in gap, and the CREATE-only table-name behavior — none reachable by mocked tests.
- **Security posture above spec.** Owner auth restricted to read-only (closing a generation-escalation hole flagged by Amplify's own deploy warning), existence-leak-safe login errors, WAF rate limit scoped to the public pre-check operation.

## Challenges

1. **Manual-verification tax (Tony's pick as the one that actually hurt).** The in-app browser tooling failed in both 1.2 and 1.4; every live UI verification was done by hand. Hand-run verifications don't rerun — they become sentences in story files instead of repeatable checks. Epic 2/3 are UI-heavier, so this cost grows unless automated.
2. **Records outran reality twice.** 1.1 Round 1's table-name "fix" was recorded done but was a silent no-op for a full review cycle; Story 1.4 was marked `done` in sprint-status while its implementation sat uncommitted with a live key in the artifacts. Definition of done didn't include "committed, pushed, secrets swept."
3. **1.2's five review passes (21 patches)** largely discovered a test bar (async settled states, a11y announcements, retry-state overlap) mid-review; once written into 1.3's spec, findings dropped to one. The system self-corrected, one story later than ideal.
4. **Story 1.1 was a mega-story** (backend bring-up + signup flow; 3 halted sessions on the auth↔data CloudFormation cycle). Discussed, not resolved as a defect: the epic spec required the backend to exist first, and the killers were unknowable Amplify internals, not sizing.

## Key Insight

Every serious bug this epic was caught by **adding a new kind of verification** (typecheck, live deploy, real signup) — never by more of an existing kind. Action items should keep buying new verification kinds; browser automation is the next one.
