## What Went Well

- **The complete public surface shipped** — pitch, free Quick Draw, access funnel; the full Priya flow from EXPERIENCE.md is live. Copy discipline held (byte-exact strings from the mockup/PRD, no improvised alternates).
- **Composition over construction.** 2.1 forbade forking `SpreadSelector` (one `embedded` prop, byte-identical default); 2.2 reused `Field`, SignUp's `submittingRef`/error patterns, and `invite-key-mint`'s testable `createHandler(deps)` Lambda shape. Almost nothing was invented — it was assembled, and 2.2's clean review is the payoff.
- **The Playwright foothold paid for itself immediately.** The in-app browser tooling failed again in 2.1 (same as Epic 1) — and it didn't matter, because the Chromium smoke spec covered the flow. Specs were flake-engineered up front (bounded redraw loop, no random-value assertions in the always-on gate).
- **Spec-level trap warnings worked.** The ⚠️ traps written into tasks (heading collision, duplicate ack string, Vitest-collects-e2e, accessible-name collision) were all real and all avoided — Epic 1's story-to-story intelligence transfer, still compounding.
- **Security above spec again:** structural header-injection guard (user input only in the plain-text body, fixed subject, trusted addresses), length caps, CR/LF collapsing, WAF parity on the second public operation.
- **Outcome-verification caught a silent failure.** "Confirm the email actually arrives" (not "SES returned success") is the only reason the mailbox-filtering bug was found — and the only reason the access-request signal exists today.

## Challenges

1. **"Records outran reality" recurred** (Epic 1 challenge #2). Three of 2.1's ten review patches were record-integrity fixes: deleted task checklists, a checked-but-not-performed real-account verification, stale test-count evidence. Systemic root: the real-account check was work the agent *structurally could not do* (no credentials), yet it sat unlabeled on the agent's checklist. 2.2's "Pre-dev prerequisites (Tony)" section is the structural fix — human-only work never appears on the agent's list.
2. **Environment friction bit twice at the moment of need:** 2.1's sandbox couldn't bind the dev server (`EPERM`); 2.2 stalled at live verification on an expired AWS SSO token (`InvalidCredentialError`). Both were discovered mid-story rather than at story start.
3. **One unexplained transient:** first real-account render showed `Account couldn't load` before `Retry account` recovered. Recovered cleanly, cause unclassified — low-priority investigation before Epic 3 multiplies authenticated queries.

## Key Insight

Epic 1's insight was "every serious bug is caught by a *new kind* of verification." Epic 2 refined it: **verification must check the outcome, not the API response** — SES accepted the send and the mail still vanished. Corollary: work only a human can perform must be labeled as such in the spec (Pre-dev Prerequisites), or it becomes a false checkbox.
